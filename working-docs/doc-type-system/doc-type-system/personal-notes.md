# Personal Notes

Two things said in passing on this branch, kept exactly as said, for later
use outside this working set.

> markdown is now code, just a fuzzy random form of it with the LLM as the
> stochastic compiler. The whole idea behind doc-type was to give markdown
> files structure, contracts, APIs, and typing. CLOA (related, but not the
> focus of this branch), is about embedding deterministic structure within
> in. This wraps it all up in pseudocode it's lovely. :)

> We're going to do both: the literal picture (in next turn) and the
> substrate of predicates. We need both because the user naturally thinks
> in the first and the second allows us to generalize and extrapolate
> beyond specific examples of the distribution into a general description
> of the entire distribution.

Six more, shorter, from the same conversations:

- **Linear work.** "I never get hands off the wheel... I should be just
  describing not what you should do but structure I want enforced...
  that kind of specification is durable and it sticks around even when
  the conversation is over."
- **The big fuzzy target.** "When the goal is large and unspecified and
  high dimensional, we cannot expect the loop to even know how to get
  to the target state much less get there."
- **In the loop the whole time.** "Wow! So we've been doing a loop here,
  but I've been in the loop the whole time!!!"
- **Not only predicates.** The software factory "is a mixture" of a
  target-state description and predicates along the way.
- **Point vs. distribution.** "a reference model shows one point in the
  distribution, the predicates describe the distribution."
- **Spec-driven development led me astray**, and Matt Pocock's specs as
  "targets in his state space."
