# PLAN.md — Adopt the Open Knowledge Format (OKF) for dev-playbook

**Status:** working plan. **Transient** — delete before the final PR. NOT an OKF
concept doc (no frontmatter; excluded from the bundle and the type-lint).

**Branch:** `worktree-adopt-okf` (worktree at `.claude/worktrees/adopt-okf/`).
No autonomous-commit authority — pause for human review/commit after each phase.

**Goal:** Convert dev-playbook's agent-navigated documentation into one OKF
bundle, so an agent can triage by frontmatter and navigate via per-directory
`index.md` listings with minimal context bloat. Scope is THIS repo only; other
workspace repos adopt later.

## Locked decisions (the contract)

### Bundle
- **One bundle = the whole repo.** Not split. (More bundles ⇒ more cross-bundle
  citations; not worth it.)
- **Concept docs (OKF; carry frontmatter):** `standards/`, `docs/`, `workflow/`,
  `protocols/`, `harness-recipes/`, `tools/` doc(s), every dir `README`, root
  `README`, `CONTEXT.md`.
- **Harness-owned (in the repo, not concept docs; no OKF frontmatter):**
  `CLAUDE.md` (any), `SKILL.md` + skill `references/`, `rules/`, `settings*.json`,
  `hooks/`, `.js` workflows, Python code under `tools/`. NOT "out of the bundle" —
  in the bundle, just not concept docs. Phase F states this boundary explicitly.

### Type registry — 8 concept types
Title Case, acronyms upper (matches OKF SPEC.md style, e.g. `BigQuery Table`,
`API Endpoint`).

- **`Standard`** — A normative conformance target: rules a repo, doc, or agent
  must follow, that a reviewer or linter could cite to reject work.
- **`README`** — The GitHub-rendered landing/orientation doc for a directory or
  the repo; prose, with any listing delegated to a sibling `index.md`.
  Role-based: filename `README.md` ⟺ `type: README`.
- **`ADR`** — An immutable, numbered record of one architectural decision and its
  rationale.
- **`Guide`** — A teaching or procedure doc you read to learn how to do or think
  about something, not to be measured against.
- **`Survey`** — An evaluative analysis of options or tradeoffs, gathered to
  inform a decision.
- **`Protocol`** — A formal algorithm for structured human–agent collaboration.
- **`Vocabulary`** — The canonical definitions of the workspace's domain terms
  (lives in `CONTEXT.md`).
- **`Recipe Description`** — A prose description of a reusable harness pattern;
  the recipe itself is the backing code/skill/workflow, this doc only describes it.

Reserved, **typeless** (no frontmatter): `index.md` (directory listing).
`log.md` is NOT used (see parked).

### Frontmatter field profile (per concept doc)
- `type` — REQUIRED; one of the 8 above.
- `title` — yes.
- `description` — yes (the one-liner that powers triage + the `index.md` listings).
- `tags` — NO. `timestamp` — NO.
- `resource` — a path or URI to the underlying asset a doc describes (a repo-root
  path like `/dotfiles/dot-claude/workflows/ralph-loop.js`, or an external URI).
  Optional in general; required on `Recipe Description`. A companion skill, if any,
  is linked in the body — NOT in `resource`. (Matches `document-types.md`.)

### Links
- Intra-repo doc→doc links: **OKF `/`-from-repo-root** (e.g.
  `/standards/doc-conventions.md`).
- Cross-repo refs: stay `~/workspace/…` (treated as OKF citations).
- `ref-check` rewrite to understand both classes is **deferred to phase G**.

### Indexes
- `README.md` keeps its name + gets `type: README`; its **listing moves to a
  sibling typeless `index.md`**.
- `index.md` is **authored** to the documented format from child frontmatter
  `description`s — NOT generated by a committed tool (see F7). Phase D produced the
  current 9 via a throwaway script; going forward they are hand-authored and a
  Phase-G **staleness checker** (pre-commit) fails on drift.
- Root `index.md` declares `okf_version`.

### Type-registry doc + lint
- Allowed types live in **`standards/document-types.md`** (`type: Standard`): the
  8 names + one-line definitions + the field profile.
- Lint (phase G): assert every concept's `type` ∈ the set declared there; wire
  into pre-commit. Semantics = **exact membership** (F6).

### Editorial rule
- **Stale content is deleted, not archived.** No decision-log narration in living
  docs; a one-line "since refactored / dropped" is the most.
  **Exception: ADRs are immutable** — never edited or scrubbed.

### F — locked from grill (`/grill-with-docs`)
- **F1 scope.** Write OKF as the *portable* workspace doc standard. Transient
  breakage of the one other repo (spec-tools, handled later) is acceptable — do
  not hedge for it.
- **F2 link rule.** In-bundle **Link** = `/`-from-root (resolves against the
  reader's *own* checkout root; worktree-safe). Cross-repo **Citation** =
  `~/workspace/<repo>/…` (that repo's main checkout). Both **inline**, no
  citations section. A self-reference MUST NEVER use `~/workspace/dev-playbook/…`
  (in a worktree it jumps to main = wrong checkout). Grounded in OKF's Link vs
  Citation distinction (SPEC §2, §5, §8); `/`-absolute is OKF's *recommended* form.
- **F3 boundary.** Concept doc = prose knowledge you read to understand.
  Harness-owned = a tool consumes it as config or runs it as code (`CLAUDE.md`,
  `SKILL.md` + skill `references/`, `rules/`, `settings*.json`, `hooks/`,
  `.js`/`.py`, non-md config). Bundle = the repo; the concept-doc set = the repo
  minus harness-owned. `CLAUDE.md` is the worked "prose-but-out" example.
- **F4 homes.** No third doc. `document-types.md` = vocabulary (types + field
  profile). `repo-documentation.md` = structure (bundle, boundary, `index.md`,
  two link classes) + its existing per-repo content; it points to
  `document-types.md` for the registry, never repeats it.
- **F5 Files table.** Add a type column (concept `type` vs. harness-owned).
  DELETE the `ROADMAP.md` and `BUSINESS_CONTEXT.md` rows — those file kinds are
  going away. Leave the `specs/` row deferring to SDD (out of OKF scope here).
- **F6 registry.** Extensible; single source of truth = `document-types.md`;
  adding a type = editing that doc. Phase-G type-lint = **exact membership**
  against it (settles the parked subset-vs-exact item).
- **F7 index.md.** Authored to the documented format (NOT generated). A Phase-G
  **staleness checker** (pre-commit hook, alongside `ref-check`/type-lint) fails
  the commit when an index omits a concept doc in its dir, lists a stale one, or a
  listed description doesn't match the child's frontmatter. Content rule: list the
  dir's README + each concept doc with its `description`; link child dirs' indexes;
  recurse into a subdir only when it has no index of its own (the Phase-D rule).
- **F8 adr-conventions.** Template gains `type: ADR` + `title` + `description`
  frontmatter; `status` stays an optional extra key. ADR index responsibility
  moves `docs/adr/README.md` → `docs/adr/index.md` (README becomes narrative).
  Accept the mild description/body echo on one-sentence ADRs (description = triage
  surface, body = the record). Existing 7 ADRs already conform (Phase C).
- **F9 doc-conventions.** Unchanged — it has no links to convert and its voice
  rules are boundary-agnostic (govern all authored prose, concept or harness-owned).
- **F10 skill-conventions.** (a) Convert its own 3 cross-refs to `/`-root
  (E-deferred). (b) Add one line: skills are harness-owned / out of the OKF bundle,
  so a `SKILL.md` keeps its Claude Code frontmatter (`name`/`model`/…), NOT OKF
  frontmatter. (c) Keep the skill link rule as a *pointer* to `repo-documentation.md`
  — the authoritative two-class rule + the "skills have no fixed repo root" rationale
  live there, not restated here.
