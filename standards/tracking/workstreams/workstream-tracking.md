# Workstream Tracking

A worklist item of a workstream, one piece of work a workstream tracks.
A workstream tracks its work in its head file, `WORKSTREAM.md`: an item
waits under `Planned` and moves to `Completed` when it is done. That
the worklist is in the head file only is
[The worklist in the head file only](/standards/knowledge-organization/documentation-sets/workstream-files.md#the-worklist-in-the-head-file-only);
the form of an item is
[A worklist item opens with its bold name](/standards/doc-type/workstream-conventions.md#a-worklist-item-opens-with-its-bold-name).
Work tracked on GitHub is
[GitHub Tracking](/standards/tracking/github/index.md), the other way
to track work.

> **Why.** Two trackers for one piece of work give it two states, and
> no reader can tell which one is true. Each way keeps its own work,
> so the head file is the one place to look for a workstream's work.

## Tracked in its head file alone

A worklist item links to no GitHub issue, and no GitHub issue tracks
the work the item names.
