Rule set the ordered rules; first match wins

Purpose

Strips secrets and PII from text before it is shared, so a log or transcript can go into an issue or chat without leaking. Exists because people paste sensitive output by hand, and a machine pass catches what an eye misses.

Behavior verified: run exhibit: constructed

$ printf 'user=ada db_pass=hunter2 ok\n' | redact --stdin
user=ada db_pass=«redacted:password» ok

A real secret can't be committed, so the input is synthetic; the transform is a live run — one hit, masked by its rule's label (mask).

API

Rule(pattern: str, label: str)
A secret pattern and the label its matches collapse to.
load_rules(path: Path) -> list[Rule]
Read a rules file into a list of Rule.
redact_text(text: str, rules: list[Rule]) -> Redaction
Mask every rule match in text; report how many were hit.
Redaction(text: str, hits: int)
The masked text and the number of secrets redacted.

Command grammar above, importable surface below — --rules optional, exactly one input source required, <file> repeatable. Exit 0 ok · 2 usage error.

Data flow

inputinternaloutput

One entry point (redact) scans the input text against the rule set and masks every hit; only the endpoints touch the outside.

Module roster

cli.py — argument parsing and file/stdin I/O. core.py — the pure scan-and-mask pass. rules.py — the Rule type and load_rules.

Assessment opinion

  1. Unlisted secret formats pass through in the cleara rule catches only what its pattern describes, so a novel token shape is never masked (Rule).
  2. Rule order silently decides the labelfirst match wins, so a reordered rule set relabels or drops overlapping hits (Rule set).
  3. The command-line path ships unverifiedfile-vs-stdin and rules loading have no test; a plumbing regression is invisible (Tests).
  4. A pass reports a count, not a missthe hit count confirms what was masked, never what slipped through (Hit).
