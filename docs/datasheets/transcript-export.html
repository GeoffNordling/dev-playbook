Concepts

Session a Claude Code conversation, the unit exported by id
Keep/drop omits harness plumbing, collapses duplicate re-emissions
Rewound branch an abandoned rewind, rendered before the turn that superseded it
Ordinal-wins highest-ordinal sibling of a shared parent is the branch that stayed live
Sub-agent recursion a spawned child session expanded inline as nested subagent
Fail loud any daemon error or malformed output aborts the whole export

Purpose

Turns a Claude Code session into one self-contained XML transcript a model can read — the whole conversation, including the branches a rewind abandoned and the sub-agents a turn spawned. It exists so a session can be archived, searched, or replayed to a model without the live daemon. It reshapes AgentsView's already-parsed messages; it never reads the raw logs.

Behavior verified: run exhibit: constructed

$ transcript-export out/ 9c0c13d6-…
out/9c0c13d6-….xml

out/9c0c13d6-….xml:
<session id="9c0c13d6-…" project="dev_playbook" agent="claude"
         branch="main" messages="3" compactions="0">
  <user ord="0" command="/model"></user>
  <user ord="1">Fastest way to screenshot to clipboard on Fedora?</user>
  <assistant ord="2" model="claude-sonnet-5">Ctrl+Shift+PrtScn selects

A real session is private, so the input is a small faithful stand-in and the run is live; one file per id is printed, and the header, per-turn ord/model, and slash-command form are the real schema.

API

render_session(session_id: str, runner=subprocess.run) -> str
main(argv: list[str], runner=subprocess.run, render=render_session) -> int

Command grammar above, importable rendering entry below: pick sessions three mutually-exclusive ways, session ids repeatable. Exit 0 ok · 2 usage error · nonzero on any daemon or XML failure.

Shape

inputinternaloutput

One entry point (render_session) drives the agentsview client, then normalize, keep/drop, and fork reconstruction feed the renderer; the dashed edge is the sub-agent recursion, and only the endpoints leave the process.

Module roster

client.py — the agentsview subprocess boundary (session list/get/messages, paged to exhaustion). model.py — normalizes raw rows into frozen Message/ToolCall records and collapses resume re-emissions. classify.py — per-message kind and the keep/drop policy. forks.py — rewind-fork reconstruction into a live path plus rewound branches. render.py — pure XML rendering of turns, tool calls, thinking, and timeline markers. transcript.py — the impure orchestrator that fetches, reconstructs, renders, and recurses into sub-agents. cli.py — session selection and file writing.

Assessment opinion

  1. A missing sub-agent aborts the whole exporta spawned child not in the local store makes the fetch fail loud, so one broken link loses the entire transcript, not just that branch (Fail loud, Sub-agent recursion).
  2. Fork order rests on an untested assumptionreconstruction trusts that the highest-ordinal sibling stayed live; if that ever fails, branches are relabeled or buried silently (Ordinal-wins).
  3. The real daemon shape is pinned by one canaryevery other test uses hand-built rows frozen at agentsview v0.34.5, so a schema drift is caught only by the live test, which CI skips (Tests).
  4. Tool output is truncated and sanitizedbodies over 2000 chars are cut and illegal control bytes stripped, so the transcript is a lossy view (chars still records true length).
  5. Keep/drop can silently discard a real turnanything typed as a system row, or an exact adjacent repeat, is dropped; a genuine message matching those shapes disappears (Keep/drop).
