Concepts

Canonical label set the fixed list of metadata + phase labels a repo's labels must match
Closed-world labels in the set are created or updated; anything else in the repo is deleted
Structure report the class/function/signature/docstring listing griffe-outline prints for a package
Alias a re-exported name skipped so each member lists once, at its real definition site

Touch surface

Reads the repo's existing GitHub labels — name, color, description (bootstrap-labels, gh label list); a Python package's source tree, via static analysis, never executed (griffe-outline)
Writes the repo's live GitHub labels — creates, edits, deletes to match the canonical set (bootstrap-labels); the structure report to stdout (griffe-outline)
Spawns gh — one process per label list/create/edit/delete (bootstrap-labels); none (griffe-outline)
Net GitHub API, indirectly through gh's own calls (bootstrap-labels); none at runtime — uv run --script may fetch griffe from PyPI on first use, cached after (griffe-outline)
Env none read directly by either script — gh (bootstrap-labels' subprocess) resolves its own auth outside this script's control
Deps gh CLI, external binary, must be authenticated (bootstrap-labels); griffe, pinned by inline script metadata, installed on first run (griffe-outline)

Tests

None. no test file references either script

Purpose

Two independent, single-file utility scripts with no shared code between them. bootstrap-labels enforces the workspace's GitHub label scheme in the current repo — a closed-world sync that creates, updates, and deletes to match a canonical set. griffe-outline prints a Python package's class/function structure — signatures and first-line docstrings — for documentation and quick inspection, without executing any of it.

API

bootstrap-labels

No flags, no arguments — every invocation is identical. Exit 0 ok · 1 on any gh failure (uncaught).

griffe-outline

<package> required; --search <path> optional, repeatable. Exit 0 ok · 1 load failure · 2 usage error. Neither script is importable — both are standalone entry points, not part of a package, so no signature list applies.

Shape

inputinternaloutput

Two unconnected tracks sharing a directory, not a pipeline: bootstrap-labels (top) syncs GitHub labels; griffe-outline (bottom) turns a package into a structure report. Neither touches the other's inputs or outputs.

Canonical labels

Metadata (grey): category:bug, category:enhancement, mode:sdd, mode:direct, tests:yes, tests:no. Phase (yellow): phase:intake, phase:sdd-specs, phase:sdd-spec-review, phase:sdd-tdd, phase:sdd-code-pr-review, phase:design, phase:tdd, phase:build, phase:code-pr-review.

Assessment opinion

  1. No tests guard either scripta change to the label-sync logic or the structure-report format has nothing to catch a regression (Tests).
  2. A `gh` failure can leave label sync half-appliedcreates/updates run in one pass and deletions in a second; an uncaught failure partway through a pass leaves the repo's labels in whatever state the prior calls reached (Closed-world).
  3. Every invocation mutates the repo's live labels immediatelythere's no preview of what a sync would create, edit, or delete before it happens (Canonical label set).
  4. An unresolvable alias vanishes from the structure report with no noteanything griffe can't resolve is silently dropped, so a re-exported name can be missing with nothing flagging it was skipped (Alias).
  5. griffe-outline's one dependency arrives over the network on first useuv run --script fetches griffe from PyPI the first time it runs on a machine, despite the tool otherwise never touching the network.
